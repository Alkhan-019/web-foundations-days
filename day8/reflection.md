# Day 8 Reflection

The most difficult concept in this course was understanding concurrency and how to prevent two users from purchasing the same seat simultaneously. Initially, I found it challenging to see how separate requests could both find a seat available. I improved my understanding by breaking the process into steps and learning how database transactions, row-level locks, and uniqueness constraints protect shared data.

Based on the feedback on my capstone, I would improve the completeness and technical detail of my system design. The feedback highlighted that my traffic estimates and requirements were strong, but my original document lacked the API specification, relational database schema, double-booking prevention strategy, architecture diagram, and trade-off analysis. I would address this by documenting the endpoints, defining table relationships, explaining the SQL locking process, and showing how the system handles peak demand.

Next, I plan to deepen my knowledge of backend development, SQL, API testing, and application deployment. I want to build a working version of TicketHub so I can test seat reservations, payment retries, and expired holds in practice. I will also continue improving my Git and GitHub workflow, writing clearer documentation, and testing my projects before submission. These skills will help me build reliable applications that can support real users.
